# Z024 review and fixes — 2026-09-22

This is a source/host review, not proof of absence of defects or permission to
operate an accumulator. Runtime remains Z023; Z024 CAN is still disabled.
Temperature scanning remains enabled in the existing validation profiles.

## Confirmed local findings and corrections

| Finding | Correction | Evidence |
|---|---|---|
| Recovery could acknowledge a new callback fault as an old fault and enable TX using stale readiness evidence | Added `recovery_begin` before physical checks; final recovery rejects any subsequent fault, including a repeat of the same bit | Directed same-bit race test; behavioral mutation; callback concurrency/TSan |
| Cached RX diagnostics retained a valid bit beyond sample expiry or recovery | Added owner-only `copy_rx` with age/fault checks; recovery clears RX availability | Exact 100/101-ms expiry, backwards-time, fault and recovery tests |
| Codec-to-publication delay was missing from sample age | Publication now requires the codec timestamp and includes both pre-publication and send-queue residence | 80-ms enqueue/90-ms send and stale/future encoding tests; mutation |
| Estimator narrowed an arbitrary double charge-derived current before validating representability | Guard cumulative subtraction against overflow and reject values outside the producer's 1500-A limit before float conversion | DBL_MAX, opposite-sign extrema and FLT_MAX tests; floating-exception checks; ASan/UBSan |
| Z023 leaked Zephyr `k_tid_t` through the public platform header | Moved owner binding into `ams_private/supervision_owner.h`; updated composition root and tests | Original architecture checker now passes without weakening it |

The CAN defects concern the portable integration boundary, which has no live
hardware caller yet. The estimator is advisory. These fixes do not promote any
safety evidence or BMS/balance authority. The previous completion-event deadline
fix remains covered: timely event at 100 ms accepted even if observed late;
completion event at 101 ms rejected.

## Pinned driver review: unresolved integration requirements

The source-download blocker is resolved. Official Zephyr v4.4.0 CAN sources were
fetched directly from GitHub at commit
`684c9e8f32e4373a21098559f748f06915f950c9`.
An unmodified bxCAN source copy, its upstream manifest and license are included
under `oracle/z024/zephyr-v4.4.0/`.

The pinned `can_stm32_recover` returns zero after entering init successfully even
when the bus-off wait immediately times out; it also ignores leave-init failure.
`probe_z024_upstream_recovery.py` compiles the exact extracted function with a
minimal register/time fake and reproduces both cases. This is a reproduced
upstream hazard, NOT a successful recovery test or validation of hardware.
The application must positively check controller state and old-request settlement;
a successful return code alone is insufficient. Upstream source was not patched
or silently substituted in this review.

Other inspected integration constraints:

- Send/start/stop/recover take an internal mutex with `K_FOREVER`. A finite send
  timeout only bounds the mailbox semaphore wait. Sole ownership helps, but the
  adapter still needs a documented whole-call timing argument and target proof.
- Stop invokes failure callbacks before requesting hardware mailbox abort, so
  callback delivery is not by itself proof that all old hardware requests settled.
- The RX ISR drains while its hardware FIFO is nonempty. A bounded application
  queue/drain loop does not prove a bounded hardware IRQ under sustained traffic.
- Callback user data is a pointer on this STM32 target. A 64-bit cookie cannot be
  truncated into it or replaced by a pointer to a mutable/reused request slot.

These are requirements for the unfinished adapter, not grounds for enabling it.

## Review coverage and reproducibility

Manually inspected CAN scheduler/transport/codec state transitions, shared
supervision state and publication boundaries, current-window validation,
measurement-store ownership, segment estimator input handling, and pinned driver
completion/recovery paths. Automated GCC analysis compiled all 31 portable
production translation units with strict C11 diagnostics. Source hashes are in
`evidence/PORTABLE_REVIEW_ANALYZER_REPORT.json`.

The Z024 canonical campaign includes production-code directed tests,
100,000 scheduler differential transitions, 21 compiled behavioral negative
controls, ASan/UBSan, callback concurrency/TSan, and Z023 through earlier inherited
campaigns. Current reports and logs are under `evidence/`.

  manufacture a pass. Its report and complete log are preserved as
